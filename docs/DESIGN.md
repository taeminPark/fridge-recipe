## 개요

내가 가진 재료를 입력하면, 그 재료와 기본 양념만으로 지금 바로 만들 수 있는 한식 레시피를 보여주는 PWA다. 아이폰 홈 화면에 추가해 앱처럼 쓴다.

- **문제**: 기존 레시피 앱은 요리를 먼저 고르고 재료를 사러 가는 구조라, 냉장고에 있는 걸 처리하기 어렵다.
- **접근**: 요리 → 재료가 아니라 재료 → 요리. 결과에레시피 상세까지 동작하는 MVP를 로컬에서 띄운다.는 "지금 만들 수 있음"이 먼저 나온다.는 "지금 만들 수 있음"이 먼저 나온다.

## 차별화 포인트

한식 레시피를 "내 재료로만" 엄격하게 거르되, 기본 양념과 "1개만 더" 구간으로 결과가 비지 않게 하는 것이 핵심이다.

| 포인트 | 내용 | 기존 앱과 차이 |
| --- | --- | --- |
| 한식 + 내 재료만 | 보유 재료로 100% 충족되는 레시피만 메인 결과에 표시 | SuperCook은 한식이 약하고, 냉쿡은 부족 재료가 있어도 추천 |
| 기본 양념 자동 포함 | 간장·소금·설탕·참기름·식용유 등은 "항상 있음"으로 기본 체크, 설정에서 끄기 | 양념까지 입력하게 하면 결과가 거의 안 나옴 |
| 1개만 더 | 부족 재료가 정확히 1개인 레시피를 별도 섹션으로, 무엇이 없는지 표시 | 엄격한 필터의 답답함을 보완 |
| 재료 동의어 처리 | 대파/파, 계란/달걀, 돼지고기 앞다리/돼지고기 등을 하나로 매칭 | 이름이 조금만 달라도 매칭 실패하는 문제 방지 |
| 공공 레시피 DB | 식약처 식품안전나라 조리식품 레시피 API를 정제해 사용 | 저작권 걱정 없는 한식 데이터 |

## 사용자 흐름과 화면

화면은 4개, 하단 탭 3개(내 재료 · 요리찾기 · 설정)로 끝낸다.

1. 내 재료 화면에서 재료를 요"검색해 추가한다 (자동완성, 카테고리 칩으로도 선택).검색해 추가한다 (자동완성, 카테고리 칩으로도 선택).
2. 요리찾기 탭을 누르면 즉시 결과가 나온다 (버튼 없이 재료가 바뀔 때마다 재계산).
3. 결과는 "지금 만들 수 있어결과는 "지금 만들 수 있어와 "1개만 더 있으면" 두 섹션으로 나뉜다.
4. 레시피를 누르면 상세 화면에서 재료(있음/없음 표시)와 조리 순서를 본다.
5. 다 쓴 재료는 상세 화면에서 바로 "다 썼어요"로 내 재료에서 뺀다.

| 화면 | 주요 요소 |
| --- | --- |
| 내 재료 | 검색창 + 자동완성, 카테고리 칩(채소·육류·해산물·유제품·가공식품), 보유 재료 칩 목록(탭하면 삭제) |
| 요리찾기 | 섹션 2개, 카드에 요리명 · 조리시간 · 사용하는 내 재료 수 · 부족 재료(1개만 더 섹션) |
| 레시피 상세 | 재료 목록(보유 체크 표시), 조리 단계, "다 썼어요" 버튼 |
| 설정 | 기본 양념 목록 켜고 끄기, 데이터 초기화 |

## 레시피 매칭 로직

레시피의 필수 재료 중 "내 재료 + 기본 양념"에 없는 개수를 세서, 0개면 지금 가능, 1개면 1개만 더, 2개 이상이면 숨긴다.

&#91;embedded content: 매칭 흐름 · 결과 3갈래\]

선택 재료와 기본 양념은 부족 개수에 넣지 않으므로, 결과가 비는 일이 줄어든다.

- **정규화 먼저**: 모든 재료명은 재료 사전의 표준 ID로 바꾼 뒤 비교한다 (대파·쪽파·파 → `pa` 같은 규칙은 사전에서 관리).
- **필수 vs 선택**: 레시피 재료에 `optional` 표시가 있으면(깨, 고명, 후추 등) 부족해도 감점하지 않는다.
- **정렬**: 지금 가능 섹션은 "사용하는 내 재료 수" 많은 순 → 조리시간 짧은 순. 냉장고를 많이 비우는 요리가 위로 온다.
- **성능**: 레시피 수천 개 수준까지는 브라우저에서 매번 전체 계산해도 충분하다. 서버 불필요.

```ts
function match(recipe, myIds: Set<string>, pantryIds: Set<string>) {
  const required = recipe.ingredients.filter(i => !i.optional);
  const missing = required.filter(i => !myIds.has(i.id) && !pantryIds.has(i.id));
  const used = required.filter(i => myIds.has(i.id)).length;
  if (missing.length === 0) return { tier: 'now', used, missing };
  if (missing.length === 1) return { tier: 'oneMore', used, missing };
  return null;
}
```

## 데이터 설계

데이터는 정적 JSON 파일 2개(재료 사전, 레시피)로 앱에 포함하고, 사용자 상태만 브라우저에 저장한다.

**재료 사전** `ingredients.json`

```json
[
  { "id": "pa", "name": "대파", "aliases": ["파", "쪽파"], "category": "채소", "isPantry": false },
  { "id": "egg", "name": "달걀", "aliases": ["계란"], "category": "유제품·달걀", "isPantry": false },
  { "id": "soy_sauce", "name": "간장", "aliases": ["진간장", "양조간장"], "category": "양념", "isPantry": true }
]
```

**레시피** `recipes.json`

```json
[
  {
    "id": "r001",
    "name": "대파 달걀볶음밥",
    "minutes": 15,
    "ingredients": [
      { "id": "rice", "amount": "1공기" },
      { "id": "egg", "amount": "2개" },
      { "id": "pa", "amount": "1/2대" },
      { "id": "soy_sauce", "amount": "1큰술" },
      { "id": "sesame", "amount": "약간", "optional": true }
    ],
    "steps": ["대파를 송송 썬다", "기름에 파를 볶아 파기름을 낸다", "달걀을 스크램블한 뒤 밥과 간장을 넣고 볶는다"],
    "source": "manual"
  }
]
```

**사용자 상태** (localStorage)

- `myIngredients`: 보유 재료 ID 배열
- `pantryOff`: 기본 양념 중 사용자가 끈 ID 배열

**레시피 데이터 확보 순서**

1. 오늘 저녁: 클로드코드에게 자주 해먹는 한식 30\~50개를 위 스키마로 직접 작성하게 한다 (API 없이 바로 시작).
2. 다음 단계: 식품안전나라 조리식품 레시피 API를 빌드 스크립트로 한 번 받아 정제한다. 재료가 자유 텍스트 문자열로 와서 파싱·사전 매핑이 가장 큰 작업이다 (필드 구조는 API 문서로 확인 필요).
3. 매핑 안 된 재료명은 `unmapped.txt`로 뽑아 사전에 별칭으로 추가하는 루프를 돈다.

## 기술 스택과 프로젝트 구조

서버 없는 정적 PWA로 만든다. 운동기록 앱과 같은 방식으로 홈 화면에 추가해 쓰고, 개발 중엔 미리보기 창에서 실시간으로 확인한다.

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | React + Vite + TypeScript | 핫 리로드가 빨라 미리보기로 바로 확인 |
| 스타일 | Tailwind CSS | 모바일 화면 빠르게 구성 |
| PWA | vite-plugin-pwa | 홈 화면 추가, 오프라인 동작 |
| 저장 | localStorage | 로그인·서버 없이 기기에 저장 |
| 배포 | GitHub Pages 또는 Vercel | 무료, 정적 호스팅 |

```text
fridge-recipe/
├─ docs/DESIGN.md          # 이 설계문서
├─ public/                 # 아이콘, manifest
├─ src/
│  ├─ data/
│  │  ├─ ingredients.json
│  │  └─ recipes.json
│  ├─ lib/
│  │  ├─ normalize.ts      # 재료명 → 표준 ID
│  │  ├─ match.ts          # 매칭·정렬
│  │  └─ storage.ts        # localStorage 래퍼
│  ├─ pages/
│  │  ├─ MyIngredients.tsx
│  │  ├─ Results.tsx
│  │  ├─ RecipeDetail.tsx
│  │  └─ Settings.tsx
│  └─ App.tsx              # 하단 탭 + 라우팅
└─ scripts/
   └─ import-foodsafety.ts # 2단계: 공공 API 정제
```

## 개발 단계

오늘 저녁은 샘플 레시피로 핵심 흐름(입력 → 매칭 → 상세)만 끝내고, 공공 데이터 연동은 다음으로 미룬다.

**오늘 저녁 MVP**

- [ ] 프로젝트 생성 (Vite + React + TS + Tailwind), 미리보기 실행
- [ ] 재료 사전 약 150개 + 샘플 레시피 30\~50개 JSON 작성
- [ ] 정규화·매칭 로직 + 단위 테스트 (동의어, 기본 양념, 선택 재료 케이스)
- [ ] 내 재료 화면: 검색 자동완성, 칩 추가·삭제, localStorage 저장
- [ ] 요리찾기 화면: 두 섹션, 정렬
- [ ] 레시피 상세 + "다 썼어요"

**이후 로드맵**

1. 설정 화면, PWA 설정(아이콘·오프라인), 배포 후 아이폰 홈 화면 추가
2. 식품안전나라 API 정제 스크립트로 레시피 확장
3. 편의 기능: 즐겨찾기, 조리시간 필터, 음성으로 재료 추가
4. 확장 아이디어: 냉장고 사진으로 재료 인식(AI), 유통기한 임박 재료 우선 추천
